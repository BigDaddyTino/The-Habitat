# Deep Application Audit, Architecture Review & Safe Cleanup

**Audit date:** 2026-08-13  
**Scope:** Entire `C:\The Habitat` repository, including applications, shared packages, Prisma schema and migrations, service definitions, deployment/backup scripts, documentation, dependency graph, and configured integration checks.  
**Method:** Static review, history/blame checks where intent was unclear, sequential build/test gates, dependency and migration audits, read-only production-data measurements, and the repository's sanitized connection audit. No production deployment, database mutation, migration, credential rotation, or data deletion was performed.

## 1. Executive summary

The Habitat has a sound security boundary and a coherent architecture: public traffic terminates at the Next.js application, the worker owns background/provider work, and game-machine control is restricted to an authenticated private agent with fixed routes, fixed actions, and allow-listed Windows services. The code consistently distinguishes `SLEEPING` from unexpected failure and generally labels provider limitations honestly.

The audit found no unresolved critical issue. It found one high-impact authorization defect: an active `VIEWER` could create or use a member invitation even though the product role contract reserves member-changing actions for `USER` and `ADMIN`. That path is now role-gated end-to-end and its invitation/audit writes are atomic. Five known production dependency advisories (three high and two moderate across PostCSS and Sharp) were also eliminated with workspace-level resolutions.

The most important unresolved operational risk is telemetry growth. `ServerMetricSample` is written on the polling cadence without retention or downsampling; the live database already held 96,221 samples spanning less than three days when measured. The other notable open items are the Dragonwilds source producing no parseable player records, absence of automated CI, a CSP that needs staged browser validation, and a small set of database mutation/audit pairs that are not transactional.

## 2. Architecture map

```text
Internet browser
      |
      v
Cloudflare tunnel -> Next.js web (Auth.js, pages, route handlers, server actions)
                           |
                           v
                     PostgreSQL/Prisma
                           ^
                           |
                Worker (polling, providers, queues)
                           |
             private IPv4 + bearer authentication
                           v
            Agent on game host (fixed server keys/actions)
                           |
             Windows services, game/query ports, fixed logs
```

The command path is explicit: an authorized admin creates a typed command and audit record; the worker claims it; the worker calls one fixed agent endpoint; the agent validates the server/action pair and invokes only the configured Windows service operation. There is no request-controlled shell, RCON command, service name, port, or file path.

- Prisma schema with 61 models, 28 enums, and 36 migrations; the configured database reported the migration history current.
- 32 test files and 125 passing tests.

## 3. Critical and high-severity findings

### Finding A-01 — invitation authorization bypass (high, fixed)

- **Evidence:** `inviteMember` required only an active session; weekly-code lookup and Auth.js referral resolution likewise accepted active inviters without enforcing `USER`. The members page rendered invitation controls for every active role.
- **Impact:** A `VIEWER` could perform a membership-changing action that the documented role model and existing authorization tests reserve for `USER`/`ADMIN`.
- **Confidence:** Confirmed through source review and Git history.
- **Action:** Replaced active-session checks with `requireRole("USER")`, restricted rendering, filtered weekly-code resolution to `USER`/`ADMIN`, and rejected referrals from inactive or demoted inviters. Invitation and audit writes now share a transaction.
- **Verification:** Typecheck, 125 tests, lint, and production build pass.

### Finding D-01 — vulnerable production dependency graph (high, fixed)

- **Evidence:** The baseline `pnpm audit --prod` reported three high and two moderate advisories through PostCSS 8.4.31 and Sharp 0.34.5. See the official GitHub advisories for [PostCSS path parsing](https://github.com/advisories/GHSA-r28c-9q8g-f849) and [Sharp/libvips](https://github.com/advisories/GHSA-f88m-g3jw-g9cj).
- **Impact:** Crafted input could reach vulnerable parsing/image-processing code if an applicable execution path were exposed.
- **Confidence:** Confirmed dependency resolution; reachability was not demonstrated.
- **Action:** Added pnpm workspace overrides for PostCSS 8.5.26 and Sharp 0.35.3 and regenerated the lockfile.
- **Verification:** `pnpm why` resolves one patched version of each; `pnpm audit --prod` reports zero advisories; all repository gates pass.

There are no unresolved critical or high-severity findings in the reviewed repository state.

## 4. Broken or questionable behavior

### Finding I-01 — Dragonwilds legacy source has no parseable records (medium, open)

- **Evidence:** The sanitized connection audit can read the configured Dragonwilds log but parses zero player records.
- **Impact:** Historic/current identity ingestion cannot prove Dragonwilds player sessions from this source. The application correctly does not fabricate them.
- **Confidence:** Confirmed in the live read-only integration check; the log may simply not yet contain a real session line.
- **Action:** Retained the collector. Capture a real join/leave fixture, add parser tests, and rerun the audit after a real session.

### Finding I-02 — game-news fetch lacked bounded, validated links (medium, fixed)

- **Evidence:** The feed request had no timeout and accepted provider-supplied link values without enforcing HTTPS.
- **Impact:** A stalled upstream could occupy a server request, and malformed/non-HTTPS links could be projected into the UI.
- **Confidence:** Confirmed by source review.
- **Action:** Added a five-second timeout and HTTPS URL validation.
- **Verification:** Tests, lint, typecheck, and build pass.

### Finding I-03 — Twitch credentials were not exercised by the operator audit (low, fixed)

- **Evidence:** The connection audit checked several configured providers but did not mint a Twitch app token.
- **Impact:** Invalid credentials could remain undiscovered until the polling path ran.
- **Action:** Added a sanitized Twitch credential check and verified configured channel count without emitting secrets. The live audit now passes with zero verified showcase channels, which is reported honestly rather than as an offline claim.

## 8. Database and migration review

The 36 migrations form one linear, applied history; no drift or pending migration was reported. The schema makes strong use of unique keys, foreign keys, status enums, idempotency keys, and indexes for queue/provider/history access. No migration or destructive cleanup was warranted.

### Finding DB-01 — unbounded high-frequency telemetry (high operational priority, open)

- **Evidence:** `ServerMetricSample` is inserted on approximately the 15-second monitoring cadence and has no retention/rollup job. A read-only query counted 96,221 rows from 2026-08-10 13:48 UTC through 2026-08-13 10:57 UTC. The primary UI only needs the latest 48 indexed samples.
- **Impact:** Continuous database/table/index growth, increasingly expensive backups, and eventual maintenance/query pressure.
- **Confidence:** Confirmed in code and live data.
- **Recommendation:** Define an explicit policy before deleting data: for example, one-minute raw resolution for a short window, hourly rollups for long-term charts, and a replay-safe pruning job. Back up, test explain plans, deploy the rollup consumer, and only then prune in bounded batches.

### Finding DB-02 — some mutations and audit entries are not atomic (medium, open)

- **Evidence:** Several admin Discord/title/community/club-game actions perform the domain update and audit write as separate operations.
- **Impact:** A transient second-write failure could leave a successful administrative mutation without its audit record.
- **Confidence:** Confirmed by static review; no data inconsistency was observed.
- **Recommendation:** Convert the remaining paired operations to Prisma transactions in small, tested changes. Invitation creation was fixed in this audit as the directly touched instance.

## 9. API, authorization, and validation review

All route handlers and server actions were enumerated and inspected for session/role checks, validation, and ownership boundaries. Admin endpoints use server-side role checks. Avatar uploads constrain path, UUID, size/type/magic; Steam and Twitch callbacks bind nonce/state and exact account ownership. No `eval`, arbitrary command execution, or unsafe raw HTML sink was found.

The invitation gap described in A-01 is fixed. Remaining defense-in-depth work is centralized rate limiting for authenticated avatar, presence, and OAuth-nonce endpoints. Current invitation creation already has a 25/day database-backed limit, provider calls have persistent budgets, and the product is private; this is therefore medium/low priority rather than an exposed critical issue.

Baseline security headers were added globally: one-year HSTS, `nosniff`, frame denial, strict-origin referrer policy, and disabled camera/geolocation/microphone. A Content Security Policy was not guessed into production: Next.js inline/runtime behavior plus Three.js/Rive assets requires a report-only rollout and browser coverage first.

## 11. End-to-end data pipelines

### Monitoring and commands

Agent samples fixed game/query/process signals; worker normalizes status and writes server/player/metric state; web renders the database state. `SLEEPING` remains intentional and visually/domain-distinct from `DOWN_UNEXPECTEDLY`. Admin commands are queued and audited before private execution. The primary weakness is DB-01 telemetry retention.

### Identity and Chronicle ingestion

Fixed log sources flow through game-specific parsing, placeholder rejection, replay-safe database keys, ownership/claim reconciliation, XP/reward consumers, and privacy-aware rendering. Unverified evidence stays labeled as observed/unclaimed. Dragonwilds lacks a representative live record; Palworld durable history remains an explicitly documented coverage gap.

### Provider enrichment

Consent/visibility state gates provider ingestion. Calls use validation, timeouts, persistent request budgets, retry metadata, and last-good retention. Game news now has the missing timeout/link validation. Cross-game consumers remain disabled behind their feature flag pending real-provider shadow evidence.

## 12. Security review

Positive controls include private network placement, bearer-authenticated agent access, fixed allow lists, typed actions, database-backed roles, server-side ownership checks, bounded external fetches, encrypted transport through the public origin, and audit records for sensitive actions. No arbitrary shell, RCON, path, port, or public game-management endpoint was found.

The backup script now removes the temporary database dump from its container in a `finally` path and always removes staged secret configuration after archive attempts. This reduces secret/dump residue when copy or compression fails. Backup archives containing configuration are still only as protected as the private backup volume; encryption and restore drills remain operator policy decisions.

The deployed public endpoint lacked the newly configured headers when checked before this change. This audit did not deploy or restart services, so production must be rechecked after rollout. CSP and centralized rate limiting are the remaining application-layer hardening opportunities.

## 13. Performance and reliability

- The dominant scaling concern is unbounded telemetry (DB-01).
- External provider loops are generally sequential/bounded, time-limited, budgeted, and preserve last-good data.
- Current private-clubhouse data sizes make some eager relational page loads acceptable; add query telemetry before speculative rewrites.
- All WinSW templates previously used unbounded append logs. They now roll at 10 MB/by date and retain 14 files. Existing installed service XML is unchanged until the templates are deliberately deployed.
- The worker executes TypeScript through `tsx` in production. It works and validates, but compiling a deployment artifact would reduce runtime surface and startup variability.

## 14. Code quality and maintainability

TypeScript strictness and package boundaries are strong; cross-package domain types live in `packages/shared`, database access is centralized, and game/provider behavior is adapter-oriented. Tests cover important parsing, authorization, privacy, replay, and status semantics.

The largest maintainability hotspots are the necessarily large Prisma schema, monitoring/provider orchestration modules, and cinematic Great Hall components. They are cohesive enough that an audit-only refactor would carry more regression risk than value. There is no CI workflow in the repository, so local gates depend on operator discipline. Also, running lint/typecheck concurrently can race Prisma generation on Windows; sequential gates are reliable and should be the CI shape.
